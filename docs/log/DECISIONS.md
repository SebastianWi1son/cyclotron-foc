## 实现期（2026-08-24）— 写代码时暴露出来的

> 这几条不是开工前想出来的，是**动手写的时候才发现的语义问题**。

| # | 决策点 | 结论 | 一句话理由 |
|---|---|---|---|
| **D13** | SVPWM 语义修正 | `modulate` 增加**零序注入** `v0 = -(max+min)/2`（carrier-based SVPWM，与经典 7 段式严格等价） | legacy 与 v1 初版都是 **SPWM**（无注入，线电压上限 0.866·Vdc），语义偏离；修完线性区提到 Vdc/√3。代价：锚点②不变式从"和 = 3·center"改为"线电压 ≤ 2·limit" |
| **D14** | Config 职责边界 | **公开组件自备 Config + 原语构造传参 + 宿主平铺转发零件参数** | 信息隐藏与层级分工优先；否决了"嵌 LPFConfig"方案（1 个参数换来两层嵌套的样板） |
| **D15** | 角度存储形态 | **现算**（快照 + 纯函数派生），**不缓存** | 一致性靠"读传感器一次 → 纯函数派生"，与缓存无关；展开很便宜，缓存反而多一份状态要同步 |
| **D16** | alignment 纯算法化 | `tick` 只输出 `TickResult{state, u, v, w}` 数据；**hal 只被 `foc_core` 依赖**（单一 IO 出口） | 分层一致性：算法层零 IO、编排层单点 IO。回调形态的动机是 PC 可测注入，不是运行时多态 |
| **D17** | 对齐判稳判据 | **速度判据**：`|Δ|/dt < settle_max_speed`（实现为 `|Δ| < max_speed·dt`），配 `settle_samples` 去抖 + `settle_timeout` 兜底 | 见下方"方案演进" |

### D17 的方案演进（为什么最终选速度判据）

判稳是 FAULT 态的传感器 —— **没有判稳就无法检测"对齐失败"**，容错设计是空壳。

| 方案 | 内容 | 为什么否 |
|---|---|---|
| legacy | `|Δ| < 0.1 rad @ 50ms`（≈ 2 rad/s） | 非阻塞化后间隔变 1ms、阈值未缩放 → **语义漂移**：等于 100 rad/s 才算动，宽松 50 倍 |
| A | 保持现状（0.1 rad @ 1ms） | 静止场景够用，但匀速旋转的边界会误判 |
| B | 阈值缩放（0.002 rad） | 与 legacy 等效，但抗噪差（编码器噪声可能超） |
| **C ✅** | **速度判据**（`|Δ|/dt < 2.0`） | 速度是**与间隔无关**的物理量 —— 改控制频率不用重调阈值，语义正 |
| D | 电流判据（MCSDK 式） | v1 没有电流采样（`GetCurrentFn = nullptr`）；留作 v2 升级路径 |

**三参数三角色**：`settle_max_speed` 管准确性（零位误差上界 = max_speed·dt）·
`settle_samples` 管抗噪（连续 N 拍才信）· `settle_timeout` 管容错（迟迟不稳 → FAULT）。
